# 面试作品入口与数据看板设计

## 目标

将 Framewise 从“可运行的 AI 视频工具”升级为可直接发送给面试官的产品作品：访客可以不离开上传主流程地了解产品能力，也可在独立页面阅读产品思考；管理员可在独立标签页中查看可解释的运营数据。

## 用户与场景

- **面试官**：首次访问时快速理解目标用户、问题、当前能力与迭代判断，并能随时体验上传主流程。
- **作品作者**：演示产品时不会因打开产品说明或后台而丢失当前上传/任务页状态。
- **管理员**：使用一个公开、低权限的演示账号查看看板；不接触模型密钥或服务端敏感配置。

## 信息架构

1. 首页 `/` 保持当前上传、任务跳转及“理解—验证—重组”流程。
2. 顶部导航增加：
   - `开始体验`：同标签页返回 `/`。
   - `产品方案 ↗`：在新标签页打开 `/product`。
   - `数据看板 ↗`：在新标签页打开 `/admin`。
3. 新增 `/product`，按以下顺序叙述：问题与用户、端到端闭环、MVP 已交付、产品取舍、指标体系、三阶段路线图。
4. `/admin` 保持受 Cookie 会话保护；未登录时跳转 `/admin/login`。登录表单下方显示明确标注为“演示环境”的账号和密码提示。

## 体验与视觉

- 复用既有黑白底色、绿色强调和细边框卡片体系，避免重新设计品牌。
- 顶部导航在小屏幕保持可点击且允许简洁换行；外部工作流链接提供 `target="_blank"` 与安全的 `rel="noreferrer"`。
- 产品方案页用标题、短文和分区卡片表达，不使用依赖数据源的复杂图表；关键结论可在 30 秒内扫读完。
- 数据看板以“业务结果 → 漏斗 → 质量与成本 → 异常”排列：总览 KPI、任务漏斗、分析性能、模型成本、Remix 转化、事件采用、每日趋势、失败归因。

## 数据与安全

- 演示账号通过 `NEXT_PUBLIC_DEMO_ADMIN_USERNAME` 与 `NEXT_PUBLIC_DEMO_ADMIN_PASSWORD` 显式提供给前端；它们只可用于本项目演示环境，并必须与服务端 `ADMIN_USERNAME`/`ADMIN_PASSWORD` 对应。
- 模型 API Key、模型 Base URL、会话签名密钥一律不得传入前端或显示在页面。
- 看板继续使用现有受保护的 `/api/admin/metrics`，不新增公开指标接口。

## 验收标准

1. 首页顶部可见三个导航项；产品方案和数据看板均在新标签页打开。
2. `/product` 清楚呈现产品定位、MVP 范围、产品判断、指标和三阶段路线图，并适配移动端。
3. `/admin/login` 在表单下展示演示账号提示；登录成功进入看板，未登录访问看板仍被拦截。
4. 看板在数据为空和有数据时都能正常展示，且包含 KPI、漏斗、性能、成本、趋势和失败归因。
5. 现有上传、任务、Remix 与 admin API 测试不回归；Next.js production build 成功。
